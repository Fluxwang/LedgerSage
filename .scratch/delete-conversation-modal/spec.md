# 删除对话改用 modal 确认弹窗

Status: ready-for-agent

术语以 [`CONTEXT.md`](../../CONTEXT.md) 为准。本期不新增术语，也不新增 ADR。注意区分两种删除：「删除对话」只是让对话从用户眼前消失，永远不碰账本；「删除 (Delete)」是从账本原文里移除整笔交易。

## Problem Statement

- 在左栏对话菜单里点「删除」，弹出的是浏览器原生确认框。它的样式和应用其余部分不一致，各浏览器的外观也不同，标题栏还会显示页面地址这类无关内容。
- 原生确认框是阻塞式的，没办法显示「正在删除」的状态。删除失败时，错误跑到左栏那一行上，离用户刚才操作的位置很远。
- 账目页「删除这笔账目」用的是应用自己的弹窗，但点到蒙版就会关闭，按 Esc 反而关不掉。删除交易是改动账本原文的操作，手滑点到蒙版就丢掉确认流程，不够稳妥。

## Solution

- 新增一个通用的 modal 外壳，负责蒙版、居中卡片、Esc 关闭和默认焦点。卡片里的内容由调用方决定。
- 删除对话改用这个外壳，做成紧凑款确认弹窗（参考 Claude 网页端删除会话的样子）：标题、说明，右下角放「取消」和红色的「删除」，不带底栏。
- 账目页删除交易弹窗也改用这个外壳。版式不变，仍然带底栏，左边显示文件和行号。行为跟着统一：点蒙版不关闭，按 Esc 可以关闭。

## User Stories

1. 作为用户，我想在删除对话时看到和应用风格一致的确认弹窗，这样界面不会突然跳出一个浏览器原生对话框。
2. 作为用户，我想在弹窗标题里看到「删除对话？」，这样能确认自己点的是删除对话，而不是删除账目。
3. 作为用户，我想在正文里看到要删除的对话标题，这样不会删错对话。
4. 作为用户，我想在正文里看到「账本不受影响」，这样我知道删除对话不会改动任何已记的账。
5. 作为用户，当对话里还有待确认的记账时，我想看到「其中 N 笔待确认的记账会一并丢弃」，这样我能决定是先回去确认，还是直接删掉。
6. 作为用户，当对话里没有待确认的记账时，我不想看到关于待确认记账的那一行，这样提示更简洁。
7. 作为用户，我希望弹窗里的待确认笔数是点「删除」那一刻的最新值，而不是列表加载时的旧值，这样提示是准确的。
8. 作为用户，我想按 Esc 关闭弹窗，这样不用伸手去点「取消」。
9. 作为用户，我想点「取消」关闭弹窗，并且对话保持原样。
10. 作为用户，我不希望点到弹窗外的蒙版就关掉弹窗，这样手滑不会打断确认流程。
11. 作为用户，我希望弹窗打开时焦点在「取消」上，这样误按回车不会把对话删掉。
12. 作为键盘用户，我想用 Tab 在「取消」和「删除」之间切换，并用回车或空格触发当前按钮。
13. 作为用户，我想在点了「删除」之后看到按钮变成不可点，这样不会重复提交。
14. 作为用户，我希望删除请求进行中时 Esc 和「取消」都暂时失效，这样不会在结果返回前关掉弹窗，错过报错。
15. 作为用户，删除成功后，我想看到弹窗关闭、这条对话从左栏消失。
16. 作为用户，如果删的正好是当前打开的对话，我想自动切到一个新对话，而不是停留在已删除对话的内容上。
17. 作为用户，如果删的不是当前打开的对话，我想继续停留在当前对话，不被打断。
18. 作为用户，删除接口失败时，我希望弹窗保持打开，并在正文下方看到错误原因。
19. 作为用户，删除失败后，我想看到按钮恢复可点，这样可以直接重试，也可以取消。
20. 作为用户，如果点「删除」时拿不到对话的最新状态（例如对话已经不存在），我希望不弹窗，错误显示在左栏对应的那一行上，和现在一样。
21. 作为用户，我希望弹窗打开时背后的页面被蒙版盖住，这样注意力集中在确认操作上。
22. 作为用户，在账目页删除交易时，我希望点到蒙版也不会关闭弹窗，因为这是改账本原文的重操作。
23. 作为用户，在账目页删除交易时，我希望可以按 Esc 关闭弹窗，和删除对话的行为一致。
24. 作为用户，在账目页删除交易时，我希望弹窗打开后焦点默认在「取消」上。
25. 作为用户，在账目页删除交易时，我希望请求进行中无法通过 Esc 或「取消」关闭弹窗。
26. 作为用户，我希望账目页删除交易弹窗的版式（待删除原文预览、底栏的文件和行号、「确认删除」按钮）和现在一样。
27. 作为用户，我希望两个删除弹窗的外壳（蒙版颜色、卡片圆角和阴影、居中位置）一致，这样应用看起来是一个整体。
28. 作为用户，我希望在窄屏上弹窗不超出屏幕宽度。

## Implementation Decisions

- **通用 modal 外壳**：放在前端的通用 UI 模块里，和现有的 `Async`、`Disclose`、`Picker` 并列，并从 UI 模块的入口导出。
  - 负责：蒙版、居中卡片、Esc 关闭、打开时把焦点放到调用方指定的元素上（两个调用方都指定「取消」按钮）。
  - 不负责：标题、正文、按钮、底栏，这些由调用方作为子内容传入。
  - 接口大致是：关闭回调，加一个表示「当前不可关闭」的布尔值（busy 期间为真，此时 Esc 不触发关闭）。不提供「点蒙版关闭」的开关，点蒙版永远不关闭。
  - 复用现有的 `.scrim` / `.modal` 样式。紧凑款如果需要额外的样式，就在 modal 样式上加修饰类，不另起一套。
- **账目页删除交易弹窗**：改为使用通用外壳，内部的标题、原文预览、错误、底栏保持不变。去掉「点蒙版关闭」，新增 Esc 关闭和默认焦点在「取消」，busy 期间不可关闭。
- **删除对话弹窗**：
  - 状态归对话页统一管理（删除和切换本来就由对话页统一处理），同一时间最多显示一个删除对话弹窗。
  - 流程：
    1. 点菜单「删除」后，先重新拉一次对话列表，拿到这条对话最新的待确认写入笔数。这一步失败或对话已不存在时，不弹窗，错误显示在对应行上，沿用现在的行级错误展示。
    2. 拉取成功后打开弹窗，标题和笔数用刚拉到的值。
    3. 用户点「删除」后，弹窗进入 busy：两个按钮都不可点，Esc 也无效。
    4. 删除成功：关闭弹窗，从列表移除这条对话，作废进行中的历史请求；如果删的是当前对话，切到新对话。这些都沿用现有逻辑。
    5. 删除失败：保持弹窗打开，在正文下方显示错误，退出 busy。
  - 文案：
    - 标题：删除对话？
    - 正文：「{对话标题}」会从对话列表中移除，账本不受影响。
    - 待确认笔数大于 0 时追加一行：其中 {N} 笔待确认的记账会一并丢弃。
    - 按钮：「取消」，以及「删除」（危险样式）。
  - 不写「不可撤销」。在本项目里，「撤销」专指对账本写入做 git revert，写在这里会混淆。
- **后端**：不改动。删除对话的接口和语义（软删除、待确认写入作废、账本不动）保持现状。

## Testing Decisions

- 本期不新增测试接缝，也不引入前端测试框架。仓库目前没有前端测试，为一个弹窗专门搭建前端组件测试链路，和改动量不成比例。
- 好的验证只看外部可观察的行为（能不能关、焦点在哪、文案和错误显示在哪），不看组件内部状态。
- 验收分三层：
  1. 前端构建通过（含 TypeScript 类型检查）。
  2. 后端 pytest 全部通过。理论上不受影响，其中删除对话的后端行为已由对话管理相关测试覆盖。
  3. 在浏览器里手动走一遍以下清单：
     - 删除对话：弹窗外观是紧凑款，标题和正文文案正确。
     - 有待确认记账的对话显示笔数行，没有的不显示。
     - 打开时焦点在「取消」。
     - 按 Esc 关闭；点「取消」关闭；点蒙版不关闭。
     - 点「删除」后按钮不可点，Esc 无效。
     - 删除成功：弹窗关闭，对话从列表消失。删的是当前对话时切到新对话，不是当前对话时保持不动。
     - 删除失败（例如停掉后端再点删除）：弹窗不关，正文下方显示错误，按钮恢复，可以重试。
     - 拉取最新状态失败：不弹窗，错误显示在对应行上。
     - 账目页删除交易：版式和之前一致；点蒙版不关闭；Esc 能关闭；打开时焦点在「取消」；busy 期间不可关闭；删除和撤销流程照常工作。
     - 窄屏下看一遍，弹窗不超出屏幕宽度。

## Out of Scope

- 重命名对话的交互不变，仍然是原地编辑。
- 常用查询的删除按钮不改，仍然没有确认弹窗。
- 不提供已删除对话的恢复入口。
- 不改动删除对话、删除交易的后端接口和语义。
- 不做焦点陷阱（focus trap）或滚动锁定之类更完整的无障碍处理，只做默认焦点和 Esc 关闭。
- 不引入 UI 组件库，也不引入前端测试框架。

## Further Notes

- 参考样式：Claude 网页端删除会话的确认框。小卡片，标题加一句说明，右下角「Cancel」和红色「Delete」，没有底栏。
- 这次改动以后，应用里所有「删除」类确认都不再使用浏览器原生确认框（常用查询的删除本来就没有确认）。
