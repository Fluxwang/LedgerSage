# 02 — 收支表基础矩阵：接口 + 表格渲染

**What to build:** 用户打开统计页的「收支表」标签，看到一张「账户层级 × 连续多个月」的真实矩阵（收入、支出两棵树，汇总账户带合计与中文名），底部「待 GET /statements/income」的占位卡消失。

后端新增只读接口 `GET /statements/income`，一次返回范围内每个收支账户每个月的发生额，汇总账户合计由后端算好。账本网关新增按「账户 × 月」聚合的方法，复用现有的分录行折叠逻辑（与仪表盘分类合计、对话查询同一口径）；API 层只做参数解析与校验，不经过 Agent。前端按新响应改写收支表类型（删掉 `totals` 与 `composition`），渲染层级表格。

接口形状、金额口径、行的组织、币种处理见 [spec.md](../spec.md)「Implementation Decisions」。

**Blocked by:** None — can start immediately（与 01 互不依赖）

**Status:** ready-for-agent

- [ ] 汇总账户 = 自身分录行 + 全部子孙账户，包含直接记在汇总账户上的旧交易（先写失败测试）
- [ ] 退款冲减当月支出；收入取正数；金额为两位小数字符串，无发生额填 `"0.00"`
- [ ] 只出 `Income`、`Expenses` 两棵树，根固定显示「收入」「支出」，先收入后支出
- [ ] 未开户的中间层照样出现，显示名退回账户名最后一段；开了户的用 `name:`
- [ ] 整段范围全零的行不返回；同一父节点下兄弟按合计降序、合计相同按账户名
- [ ] 非主币种分录行不计入，其币种去重列入 `skipped_currencies`
- [ ] 同一区间上与仪表盘分类合计数字一致（回归保护）
- [ ] 参数：只接受 `YYYY-MM`；缺省最近 6 个月（含当月）；跨度超过 24 个月、`start` 晚于 `end`、`end` 在未来月份返回 422
- [ ] 当前月份作为最后一列时标 `partial: true` 并给出 `through`
- [ ] 前端渲染层级矩阵表格，占位卡移除；手动验证数字与仪表盘一致
