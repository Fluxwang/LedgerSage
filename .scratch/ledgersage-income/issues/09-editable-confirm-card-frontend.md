# 09 — 确认卡上直接改账户（前端）

**What to build:** 用户在确认卡上点一下账户就能换掉，并且一眼能看出哪些账户是系统猜的、哪些是自己说的——知道该重点核对哪一行。

确认卡目前只有「确认」和「拒绝」两个动作。加上账户选择入口：点击某笔交易的任一条分录行的账户，弹出候选列表并可选择替换，选完调用 08 的接口，预览随之刷新。

候选列表与追问的候选同源——按常用度排序、显示中文名、受方向推导约束（06）。自动补上的账户需要与用户明确给出的账户在视觉上可区分，这依赖 05 把「这个账户是猜的」这一信息传到前端。

`web/` 目前没有任何测试基建，本票靠手动验证；需要在票关闭前走一遍完整路径：收入记账 → 系统自动补错卡 → 在确认卡上改对 → 确认 → 检查账本文本。

**Blocked by:** 08、05

**Status:** ready-for-agent

- [ ] 确认卡上每笔交易的两条分录行的账户都可点击替换
- [ ] 替换后预览立即刷新为改后的内容
- [ ] 自动补上的账户与用户明确给出的账户在视觉上可区分
- [ ] 候选列表显示中文名、按常用度排序
- [ ] 替换被后端拒绝时给出明确提示，界面不进入不一致状态
- [ ] 手动走通一遍完整路径并确认账本文本正确
