# 08 — 待确认写入可编辑（后端）

**What to build:** 用户在确认之前能把系统猜错的账户换掉，换完预览立刻变成改后的样子，确认后落盘的是改后的值——而不是像现在这样只能整条拒绝、把话重说一遍。

依据 ADR 0015。两段式写入（ADR 0012）本来就把「已渲染、未落盘」的内容留在了可变的位置，当时没做编辑只是因为还没有自动补全会把错误值塞进预览。而实测表明这个安全网是必需的：把置信度阈值一路拉到极限，准确率也只有 87%，剩下约 13% 的错误来自「这次就是和以前不一样」，历史再一致也预测不到，靠调参消除不掉。

新增修改待确认写入的接口，允许替换其中某笔交易的账户。每次修改都要重新跑校验并重新渲染预览，理由与 ADR 0012 里「确认时重新校验」一致：预览不能变成一张过期的通行证。改后的账户同样要经过 04 的方向归一。修改不改变待确认写入的过期时间与确认路径。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 修改某笔交易的账户后，预览渲染出的账本文本是改后的
- [ ] 确认后落盘的内容是改后的版本
- [ ] 改成不存在的账户会被拒绝，且预览保持修改前的状态
- [ ] 改出反方向的两个账户时按 04 的规则归一，落盘符号正确
- [ ] 已确认或已拒绝的待确认写入不能再被修改
- [ ] 修改不重置 24 小时过期时限
- [ ] 多笔批次中只改其中一笔时，其余各笔不受影响
