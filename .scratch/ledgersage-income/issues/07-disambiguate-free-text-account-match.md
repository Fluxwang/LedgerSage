# 07 — 打字匹配到多个账户时再问一次

**What to build:** 用户在追问里打「银行」，系统不再默默把这笔记到 Bank-01 上，而是把匹配到的几个银行账户再问一遍让他选。

追问接受自由文本并用子串匹配账户，但匹配到多个时直接取第一个——而候选是字母序的，于是「银行」稳定地落到 Bank-01。用户完全看不出系统替他做了选择。

改为：匹配到唯一账户时照常继续；匹配到多个时把这些账户作为候选再追问一次；一个都没匹配到时明确告知并重新给出候选。

单独成票是因为它新增了一轮追问，控制流有风险——要确认重复追问不会形成死循环，也不会丢掉已经填好的另一侧账户。

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] 自由文本唯一匹配一个账户时，行为与本票之前一致
- [ ] 匹配到多个账户时再追问一次，候选即那几个账户
- [ ] 一个都没匹配到时明确告知，并重新给出候选
- [ ] 重复追问不会形成死循环
- [ ] 再追问期间已经填好的另一侧账户不丢失
- [ ] 中文显示名与英文账户名都能作为匹配依据
