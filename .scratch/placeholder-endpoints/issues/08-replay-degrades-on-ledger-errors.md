# 08 — 回放遇到账本问题时降级显示

**What to build:** 回放历史对话时，即使账本出了问题，会话也照样能打开。现在回放接口遇到还在 pending 的**待确认写入**时，会对当前账本重新跑一遍预览。有两种情况会让预览抛出异常，导致**整个会话**都打不开（返回 4xx/5xx）：

- 用户手工删掉了那笔写入用到的账户（预览校验抛出「账户不存在」）
- 账本有 bean-check 错误，而且不在缓存里（账本工厂拒绝加载）

这和「账本坏了也要能看」的原则（见 02 账本健康度）相反。改成：只有那一条待确认写入降级为「无法预览」，并且不给确认按钮；会话里其他轮次、其他待确认写入照常回放。

这个问题是在 05/06 完成后的检查中，通过读代码发现的，还没有写测试复现。动手修之前，先写出能复现的测试。

**Blocked by:** None — can start immediately（05、06 已完成）

- [x] 后端确认时的重新校验不变（ADR-0012）：即使有人绕过前端直接调用确认接口，这条写入也照样被拒绝
- [x] 每次回放请求最多获取一次账本，不在每条待确认写入上重复获取
