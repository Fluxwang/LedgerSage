# 06 — 历史对话：继续没完成的事

**What to build:** 用户回到一个历史会话时，没做完的事情还能接着做。没过期的**待确认写入**重新出现「确认 / 丢弃」按钮，点击效果和当时一样（ADR-0012：用户离开后回来还能确认）。没过期的**追问**会在输入框上方提示「上次的追问还在等你回答」，下一条消息就会作为回答，恢复原来那次运行。超过 24 小时的，都显示为只读的「已过期」或「已作废」，因为那时账本可能已经变了（ADR-0007、ADR-0012）。

**Blocked by:** 05 — 历史对话：列表与回放

**Status:** ready-for-agent

- [ ] 回放接口返回的待确认写入 `status` 按 24 小时规则判断：超过 24 小时还是 `pending` 的，读取时就报告为已过期，不需要等到确认时才发现
- [ ] 回放里还是 `pending` 且没过期的待确认写入显示可以点击的「确认 / 丢弃」，点「确认」后真正写入账本；已确认、已丢弃、已过期的只显示状态标签
- [ ] 会话挂着没过期的追问时，输入框上方显示提示；这时发出的消息恢复原来那次运行，不新建运行
- [ ] 追问已经过期时，回放里显示「已作废」，不显示输入框提示
- [ ] 左栏列表里，有未答复追问的会话带一个标记（`has_pending_ask`）
