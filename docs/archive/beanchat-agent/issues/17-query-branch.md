## 背景

M1 的图里 `query` 分支是空的，本票把它接通。

## 要做什么

- Query 节点：把用户问题转成工具调用参数，执行，把结果交给 Reply 节点组织成自然语言。
- 回复里要带**可核对的数字**（笔数、总额、区间），并在合适时给出同比/环比——设计稿里「比 7 月同期高 23%」那种。
- 结果附带后续动作按钮（「看明细 26 笔」「设个餐饮预算」），对应设计稿 `trend-actions`。
- 参数覆盖不到的问题（「周末花的是不是比工作日多」）：如实说明做不到，或拉明细自算——**不要编**。

## 完成标准

- 「这个月餐饮花了多少」返回真实数字，且与直接跑 BQL 的结果一致。
- 「我上个月为什么订阅花了150元」被正确归为 query 且能给出该笔的明细。
- 查询链路**不产生任何写入**，`git log` 无新增 commit。
