# 补齐界面上已有占位的 4 个接口

Status: done
Branch: feat/placeholder-endpoints

术语一律以 [`CONTEXT.md`](../../../CONTEXT.md) 为准。本期新增或修订的术语：工作区干净、账本健康度、收款方、缺收款方、常用查询，以及「确认」词条里的 24 小时作废规则。架构决策见 [`docs/adr/`](../../adr/)。实现拆成 4 张票，放在 [`issues/`](issues/) 下。

## Problem Statement

界面上有 5 处显示「待接口」，用户看到的是空壳：

- 顶栏的账本状态 chip 永远是「账本状态待接口」。用户在编辑器里手改账本后，如果改出了 bean-check 错误，或者留下了没提交的改动，产品完全不提醒。直到下一次 Agent 写入失败，用户才会发现。
- 统计页右栏的「账本健康度」是空卡，用户不知道账本里有多少笔支出没写收款方。
- 「前十收款方」是空卡，用户看不出钱主要花在了哪些商户。
- 「常用查询」是空卡，而且根本没有入口能存一条进去。用户每个月都要重新打一遍同样的问题。
- 左栏「历史对话」是写死的文字。一刷新页面，之前的对话就看不到了。还没确认的待确认写入、还没回答的追问，也都找不回来。可实际上这些数据后端一直都存着。

## Solution

- 顶栏 chip 显示账本此刻的健康状况：全部正常时显示绿色，并给出最近一次提交的时间；有问题时显示琥珀色，并直接说出第一个问题。点击跳到健康度卡片。
- 账本健康度卡片逐项列出：bean-check 是否通过、工作区是否干净、有几笔支出缺收款方。检查的是磁盘上此刻的账本，手改后刷新就能看到。
- 前十收款方按当前区间显示净支出，口径和旁边的分类合计一致。
- 对话里查询类的回答可以「☆ 存为常用」。右栏点击一条常用查询，就会把这句话重新问一次 Agent，按当时的账本回答。不想要的可以删掉。
- 左栏列出最近的会话，点开可以回放完整对话和工具轨迹，并且能接着聊。还没过期的待确认写入可以继续确认，还没过期的追问可以继续回答。

## User Stories

### 账本健康度

1. 作为在编辑器里手改账本的用户，我希望顶栏能告诉我账本有没有 bean-check 错误，这样我在 Agent 写入失败之前就能修好。
2. 作为用户，我希望手改账本后不用重启服务，刷新页面就能看到最新的检查结果，这样状态是可信的。
3. 作为账本已经损坏到无法加载的用户，我希望状态接口仍然能告诉我错在哪个文件哪一行，而不是整个页面报错。
4. 作为用户，我希望错误信息只显示账本内的相对路径，这样不会暴露服务器的目录结构。
5. 作为用户，我希望知道账本里是否有还没提交的手工改动，这样我知道 Agent 的提交和我的改动有没有混在一起。
6. 作为新建了一个 `.bean` 文件但忘了 `git add` 的用户，我希望这也被算作「不干净」，这样新文件不会被遗漏。
7. 作为接入存量账本的用户，我希望编辑器临时文件、向量索引这类非账本文件不会让状态一直显示「不干净」，这样提示不会变成噪音。
8. 作为用户，我希望看到最近一次提交的时间，这样我知道账本上一次落盘是什么时候。
9. 作为用户，我希望知道有几笔支出没写收款方，这样我能补全数据，让前十收款方和 Agent 的置信度更准。
10. 作为用户，我希望没有收款方的转账和收入不被算作缺失，这样提示只指向真正有问题的交易。
11. 作为用户，我希望健康度按整本账本统计，不随统计页的区间变化，因为它描述的是账本本身的状态。
12. 作为用户，我希望三项都正常时 chip 是绿色并显示「bean-check ✓ · N 小时前提交」，这样一眼就知道没问题。
13. 作为用户，我希望任意一项有问题时 chip 变成琥珀色，并直接显示第一个问题的文字，这样不用点开就知道哪里不对。
14. 作为用户，我希望点击 chip 能跳到统计页的健康度卡片，这样可以看到全部检查项。
15. 作为用户，我希望健康度卡片里每一项都有明确的「正常 / 警告」状态和一句说明。

### 前十收款方

16. 作为用户，我希望在统计页右栏看到当前区间内支出最多的 10 个收款方，这样我知道钱主要花在哪里。
17. 作为用户，我希望切换区间时排行跟着变化，并且和页面上其他数字用同一个区间。
18. 作为用户，我希望退款能从对应收款方的金额里扣掉，这样排行反映的是实际花出去的钱。
19. 作为用户，我希望收款方排行和分类合计的口径一致，这样同一屏上的数字能对得上。
20. 作为用户，我希望没写收款方的交易不出现在排行里，而不是出现一个空名字。
21. 作为用户，我希望收款方按我账本里写的原文显示，不被系统擅自合并。
22. 作为有多币种交易的用户，我希望排行只按账本的主币种计算，这样不同币种的金额不会被直接相加。

### 常用查询

23. 作为每个月都问同样问题的用户，我希望能把一句查询存为常用，这样下次一点就能问。
24. 作为用户，我希望「☆ 存为常用」按钮出现在查询类回答的结果卡上，这样我在看到答案的那一刻就能收藏。
25. 作为用户，我希望记账类的回答上没有收藏按钮，因为重放一句记账的话会重复记一笔账。
26. 作为用户，我希望即使有人绕过界面直接调用接口，也没办法把记账消息存为常用，这样重复记账在后端就被挡住了。
27. 作为用户，我希望点击常用查询时，系统按当时的账本重新回答，而不是给我看一份过期的旧结果。
28. 作为用户，我希望「这个月花了多少」这类相对时间的问题，每次都按当天的日期理解。
29. 作为用户，我希望同一句话收藏两次不会出现两条，也不会报错。
30. 作为用户，我希望把鼠标悬停在常用查询上时出现 ×，点击就能删掉它。
31. 作为用户，我希望常用查询按收藏时间倒序排列，最新收藏的排在最前面。
32. 作为用户，我希望我的常用查询只有我自己能看到、能删除，别的用户既看不到也操作不了。

### 历史对话

33. 作为用户，我希望左栏列出我最近的对话，这样刷新页面后还能找回之前的对话。
34. 作为用户，我希望每个对话的标题是我第一句话的开头，而不是一律显示「新对话」，这样我能认出哪个是哪个。
35. 作为用户，我希望列表按最近活跃时间排序，最近用过的对话排在最前面。
36. 作为用户，我希望当前所在的对话在列表里高亮显示。
37. 作为用户，我希望点开一个历史对话后能看到每一轮完整的气泡和工具轨迹，和当时实时看到的一样。
38. 作为用户，我希望在历史对话里能接着发消息，新消息归入这个对话。
39. 作为离开前没来得及确认一笔记账的用户，我希望回到这个对话时还能点「确认」，这样不用重新说一遍。
40. 作为用户，我希望已经确认、已经丢弃或者已经过期的待确认写入，显示为只读的状态标签，不能再点。
41. 作为用户，我希望超过 24 小时的待确认写入不再显示可点击的按钮，因为那时账本可能已经变了。
42. 作为离开前没有回答 Agent 追问的用户，我希望回到这个对话时能看到「上次的追问还在等你回答」，这样我知道下一句话会被当作回答。
43. 作为用户，我希望超过 24 小时的追问显示为「已作废」，这样我知道下一句话会开始一次新的运行。
44. 作为用户，我希望点「＋ 新对话」后，在发出第一条消息之前，列表里不会多出一个空对话。
45. 作为用户，我希望列表只显示最近 30 个对话，这样左栏不会无限变长。
46. 作为用户，我希望我只能看到和打开自己的对话。

## Implementation Decisions

### 账本健康度：`GET /ledger/status`

- 新建一个账本状态模块，负责对一个账本根目录做体检。它**不经过账本工厂和缓存**：每次请求都对 `main.bean` 重新运行一遍 Beancount loader。这样能看到手工改动，也能在账本首次加载就失败时照常返回结果。这个模块只读不写，不需要拿写锁。
- 用户的账本根路径解析逻辑（模板目录或接入的 `ledger_path`）要从账本工厂里抽出来复用，不能在状态模块里复制一份。
- bean-check 失败时接口仍然返回 200，内容是 `ok: false`。`message` 取第一条错误，文件路径一律转成相对于账本根目录的路径。
- 「干净」的判定：被跟踪的文件没有改动，并且没有未跟踪的 `*.bean` 文件。git 的读取复用现有的 git 调用封装，`last_commit_at` 取 HEAD 的提交时间。
- 缺收款方的统计：方向为「支出」（`to` 是 `Expenses:`）且 payee 为空的交易，按全账本累计。方向的推导规则沿用 ADR-0014。
- 返回格式如下。前端预设类型里的 `file`、`currency`、`transaction_count` 都去掉，币种和笔数已经由 `/dashboard` 提供：

```jsonc
{
  "bean_check": { "ok": false, "error_count": 2, "message": "2026/10-expenses.bean:14 Transaction does not balance" },
  "git": { "clean": true, "last_commit_at": "2026-10-14T21:03:00+08:00" },
  "health": [
    { "key": "bean_check",    "level": "ok" | "warn", "text": "…" },
    { "key": "working_tree",  "level": "ok" | "warn", "text": "…" },
    { "key": "missing_payee", "level": "ok" | "warn", "text": "…" }
  ]
}
```

- `health[].key` 是固定的枚举，前端可以按 key 给每一项挂交互。

### 前十收款方：并入 `/dashboard`

- 不新建端点。`/dashboard` 的返回里增加 `top_payees: [{ payee, amount }]`，取前 10 名，区间就是 dashboard 的 `period`。
- 账本网关新增一个「按收款方汇总净支出」的查询，复用现有的分录行折叠逻辑：前缀是 `Expenses:`，分组键是 payee。没有 payee 的交易跳过，只算主币种。按金额降序排列。
- 前端删除独立的 `topPayees()` 调用，右栏直接读 dashboard 的数据。

### 常用查询：`/saved-queries`

- 常用查询存在 SQLite 里，新增一个版本迁移，建 `saved_queries` 表（`runs.message` 列在另一个更早的迁移里加，见下文）：`id, user_id, question, run_id, created_at`，并对 `(user_id, question)` 加唯一约束。
- `GET /saved-queries` 返回 `[{ id, question, created_at }]`，按 `created_at` 倒序排列。
- `POST /saved-queries` 的请求体是 `{ run_id }`。后端检查这次运行属于当前用户，并且意图是 `query`，否则拒绝。`question` 取自这次运行的用户原话。如果同一句话已经收藏过，就返回已有的那条记录。
- `DELETE /saved-queries/{id}` 只能删除自己的记录。删除别人的或者不存在的记录，都返回 404。
- **用户原话目前没有落库**：运行的 `title` 在运行结束后会被改写成「查询账本」这样的摘要，`PARSE` 步骤也只在记账分支出现。所以要单独用一个迁移给 `runs` 表加一列 `message`（排在 `saved_queries` 之前），在创建运行时写入完整的用户原话。常用查询和历史对话回放（用户气泡）都依赖这一列。迁移之前的旧运行，`message` 为空，这些运行不能收藏，回放时用户气泡退回显示 `title`。
- 前端的 `SavedQuery` 类型去掉 `params`，`title` 改名为 `question`。查询类结果卡上加「☆ 存为常用」，右栏每一项悬停时出现 ×。

### 历史对话：`/sessions`

- `GET /sessions` 返回 `[{ thread_id, title, last_active_at, has_pending_ask }]`，按 `last_active_at` 倒序，最多 30 条。
- `GET /sessions/{thread_id}/runs` 取代前端预设的 `/sessions/{thread_id}/messages`，因为回放的单位是运行。返回按时间升序的运行，每次运行包含：自身字段、完整的步骤、关联的待确认写入及其**当前**状态（读取时按 24 小时规则判断是否已过期），以及会话级的追问状态（`active_run_id` / `pending_at`），用来判断追问是否还有效。
- 会话标题在这个会话第一次创建运行时写入，取用户消息的前 20 个字。已经存在的「新对话」不做回填。
- 继续对话不需要新机制：新消息沿用这个 `thread_id`，现有的追问恢复逻辑原样生效。LangGraph 的 checkpoint 仍然按运行隔离，回放不读 checkpoint。
- 前端切换会话时，用回放数据重建对话轮次，复用现有的结果卡和确认卡组件。「＋ 新对话」的行为不变。

### 跨切面

- 所有新端点都通过现有的当前用户依赖做鉴权，数据一律按 `user_id` 隔离（ADR-0005）。
- 这期不新增 ADR。「状态接口绕过账本缓存」是这一个端点的局部决定，记在实现票里。

## Testing Decisions

- **只用一个 seam：HTTP API。** 用应用工厂加上测试用的 `FixtureModel` 构造应用，再通过 `TestClient` 从外部发请求、断言 JSON。不单测账本网关、状态模块的内部方法。好的测试只描述外部可观察的行为，比如「手改一个文件后，接口返回 `ok: false`」，而不是「调用了 reload」。
- **准备数据的方式**：
  - 账本内容：和仪表盘测试一样，通过工厂拿到用户的账本后调用 `insert`，或者直接在 `tmp_path` 里改写、新建文件，模拟手工编辑。
  - 运行与会话：和决策历史测试一样，用 `converse()` 驱动 `/chat/stream`，配合按关键词路由意图的 `FixtureModel`，稳定地产生查询运行、记账运行和追问运行。
  - 过期：沿用待确认写入测试里改时间戳的做法。
- **要覆盖的行为**：
  - 健康度：手改出错误后，不重启就能反映出来；首次加载失败时仍然返回 200；错误信息里是相对路径；未跟踪的 `.bean` 算不干净，未跟踪的 `.txt` 不算；没有 payee 的转账不计入缺收款方。
  - 前十收款方：退款被抵扣；没有 payee 的不进排行；切换区间后结果跟着变；收款方合计不超过分类合计。
  - 常用查询：记账运行被拒绝；收藏两次只存一条；跨用户无法查看、收藏、删除。
  - 历史对话：标题取第一句；回放的轮次和步骤完整；待确认写入在 pending、已确认、已过期三种状态下返回正确；追问在有效和过期两种情况下返回正确；刷新后发的消息能恢复挂起的追问；跨用户隔离。
- **参考的现有测试**：仪表盘测试、决策历史测试、待确认写入测试、迁移测试（新增迁移要能在已有数据库上升级）。
- **前端**：仓库没有前端测试设施，这期也不引入。只用 `npm run build` 做类型检查，再加上每张票完成标准里的手工验证。

## Out of Scope

- 「超期未对账」健康项。要等「对账」有了领域定义，和资产负债页的 `reconciliation` 一起做。
- 收款方别名归一。
- 历史对话的重命名、删除、分页、搜索，以及给已有的「新对话」回填标题。
- 账本的 git remote 与同步。
- 常用查询的排序调整、分组和改名。
- 其余 10 个前端预留但没有页面使用的 `pending()` 接口（账本原文切片、账户树、收支表、资产负债、月报、导出、建议 chips 等）。
- 引入前端测试框架。
