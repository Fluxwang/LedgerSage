# 09 — 查询回复写明查询口径

**What to build:** 现在查询结果为空时，回复只有「这个范围内没有找到记录。」，既没有日期也没有账户；有结果时也只有日期，没有账户。所以模型把账户理解错了，用户必须展开工具参数才看得出来。这张票让两种回复都写明「区间 + 显示名（账户前缀）」，用户扫一眼回复就能发现理解偏差。

详见 spec 的「查询账户前缀」一节。

**Blocked by:** 07（回复里显示的是规范化后的前缀）

**Status:** done

- [x] 结果为空时：「2026-10-01 至 2026-10-22，餐饮（Expenses:Food:Dining）没有记录。」
- [x] 有结果时：「2026-10-01 至 2026-10-22，餐饮（Expenses:Food:Dining）共 5 笔，支出合计 238.00。」
- [x] 显示名取前缀本身那个账户 `open` 指令上的 `name:`；如果前缀只是一个分组、自己没有 `open`，或者没有显示名，就只显示前缀，例如「Expenses:Food 共 5 笔」
- [x] 没有账户筛选时，回复里不提账户，只写区间
- [x] 测试覆盖：带显示名的账户、没有显示名的分组前缀、没有筛选，这三种情况下空结果和有结果的文案
- [x] `pytest` 通过

## 实现与验证

- 交易查询无记录与有记录都写明起止日期和账户口径；显示名只取前缀本身的 open 元数据。分组结果明确按组计数；支出净合计保留退款符号，金额格式为两位小数。
