# 对话列表菜单、右栏账本占位收尾、统计页去掉两个空 tab、查询账户前缀修复

Status: done
Branch: feat/conversations-and-ledger-panel

术语以 [`CONTEXT.md`](../../../CONTEXT.md) 为准。本期新增的术语有两个：**对话 (Conversation)** 和 **写入历史 (Write History)**。本期还在「账户」词条里补充了按段匹配的规则。本期不新增 ADR。实现拆成 9 张票，放在 [`issues/`](issues/) 下。

## Problem Statement

- 左栏对话列表只能点开，不能改名，也不能删除。标题取的是第一句话的前 20 个字，太长，再加上一串「新对话」，用户很难分清哪个是哪个，没用的对话也清不掉。
- 对话页右栏 Ledger tab 里还有两张「这块还等后端」的空卡：
  - `GET /ledger/raw`：「写入位置上下文与查询命中的原始条目」。
  - `GET /ledger/history`：「写入历史」。
- diff 卡只显示将要写入的那几行，用户看不到它会接在哪笔交易后面。尤其在「疑似重复」提示出现时，用户还得自己去翻账本。
- 问「这个月餐饮花了多少」时，Agent 回答「这个范围内没有找到记录」。原因是查询时模型看不到账户表，编造了 `Expenses:Dining`，而真名是 `Expenses:Food:Dining`。空结果的回复既不写账户也不写日期，用户只有展开工具参数才能发现问题，会误以为这个月真的没花钱。
- 统计页的子导航里，「持仓」和「BQL 查询」是两个永远点不了的灰色 tab。这两个功能已经确定不做：持仓超出范围，BQL 见 ADR 0006。

## Solution

- 对话列表每一项右侧都有「⋯」，点开后可以「重命名」或「删除」。
  - 重命名：标题原地变成输入框，直接修改。
  - 删除：确认之后，对话从列表中消失。账本完全不受影响。
- 新对话的自动标题缩短为第一句话的前 10 个字。
- diff 卡在绿色的 `+` 行上方，用灰色显示插入点之前的几行已有原文。
- 「写入历史」卡片按时间倒序，只读地列出 LedgerSage 最近替用户做过的写入，并标明哪些已经被撤销。
- 查询时把账户表交给模型；账户前缀按段匹配；前缀不存在时如实回答，并给出相近的账户；回复里写明查的是哪段时间、哪个账户。
- 删掉 `/ledger/raw` 的占位卡片，以及「持仓」「BQL 查询」两个 tab。

## User Stories

### 对话列表

1. 作为用户，我希望鼠标悬停在某个对话上时，它右侧出现「⋯」，这样平时列表保持干净。
2. 作为用户，我希望当前打开的对话，即使鼠标没有悬停，也显示「⋯」。
3. 作为用户，我希望点「⋯」后看到「重命名」和「删除」两个选项。
4. 作为用户，我希望还没发出第一句话的「本次对话」没有「⋯」，因为它还没被保存。
5. 作为用户，我希望 Agent 正在回答当前对话时，这个对话的「⋯」不能点，避免对话在运行中途被删掉或改名。
6. 作为用户，我希望点「重命名」后标题原地变成输入框，按 Enter 保存，按 Esc 或点别处取消，不弹窗。
7. 作为用户，我希望把标题清空或只填空格时保存不成功，原标题保持不变。
8. 作为用户，我希望标题太长时看到后端给出的错误提示。
9. 作为用户，我希望改过的名字不会被系统再自动改掉。
10. 作为用户，我希望点「删除」后先弹出确认，提示里写明账本不受影响。
11. 作为用户，我希望被删的对话里如果还有没确认的记账，确认框会告诉我有几笔会被一并丢弃。
12. 作为用户，我希望对话删除后，列表里和回放里都再也看不到它。
13. 作为用户，我希望删掉当前打开的对话后，页面自动切到一个新对话。
14. 作为用户，我希望删除对话不会影响我的常用查询：从这个对话里收藏的问题依然可以用。
15. 作为用户，我希望删除对话不会抹掉已经确认写入的审计痕迹。
16. 作为用户，我希望新对话的标题只取第一句话的前 10 个字左右，这样列表更好扫。
17. 作为用户，我希望自己只能改名、删除自己的对话。

### diff 卡上文

18. 作为用户，我希望在「即将写入的 diff」里，看到插入点上方几行灰色的已有原文，这样我知道这笔会接在哪里。
19. 作为看到「疑似重复」提示的用户，我希望那笔相似的交易常常就出现在灰色上文里，这样不用离开对话页就能判断。
20. 作为用户，我希望上文不会只是一片空行。
21. 作为在空文件里记第一笔账的用户，我希望 diff 卡照常显示，只是没有上文。
22. 作为设置预算的用户，我希望预算的 diff 卡同样带上 `budgets.bean` 的上文。

### 写入历史

23. 作为用户，我希望在右栏看到 LedgerSage 最近替我做过的写入，按时间倒序排列。
24. 作为用户，我希望每一条都能看出是记账、设预算还是删除，并有一句我看得懂的摘要，而不是 `record 2 transaction(s)`。
25. 作为用户，我希望已经被撤销的写入标为「已撤销」，并显示撤销的时间。
26. 作为用户，我希望撤销操作本身不单独占一条，免得列表里出现成对的噪音。
27. 作为在编辑器里手改账本并自己提交的用户，我希望这些手工提交不出现在写入历史里。手改有没有落盘，看「工作区干净」就够了。
28. 作为用户，我希望写入历史是整本账本的：在对话 A 里记的账，切到对话 B 时也能看到。
29. 作为用户，我希望在当前对话里确认一笔写入后，写入历史立刻多出这一条。
30. 作为在统计页删除或撤销过交易的用户，我希望回到对话页时写入历史已经是最新的。
31. 作为从 BeanChat 时代迁过来的用户，我希望旧前缀的提交也能出现在写入历史里。

### 查询账户前缀

32. 作为用户，我问「这个月餐饮花了多少」时，希望 Agent 按我账本里真实的餐饮账户去查。
33. 作为用户，我希望问「食物」相关的开销时，不会把名字恰好以 Food 开头的其他账户也算进来。
34. 作为用户，我希望 Agent 用了一个账本里不存在的账户时，直接告诉我「没有这个账户」，而不是告诉我「没有记录」。
35. 作为用户，我希望在 Agent 找错账户时，它能给出我可能想查的那个账户。
36. 作为用户，我希望查询回复写明查的是哪段时间、哪个账户，这样它理解错了我一眼就能看出来。

### 清理

37. 作为用户，我希望右栏不再出现「这块还等后端 GET /ledger/raw」这张空卡。
38. 作为用户，我希望统计页不再出现永远点不了的「持仓」和「BQL 查询」。

## Implementation Decisions

### 配置

`Settings` 新增三项：

```python
conversation_title_max_length: int = Field(default=40, ge=1, le=200)   # 重命名的长度上限
conversation_title_auto_length: int = Field(default=10, ge=1, le=200)  # 自动标题截取的字数
ledger_context_lines: int = Field(default=5, ge=0, le=50)              # diff 卡上文行数
ledger_history_limit: int = Field(default=10, ge=1, le=100)            # 写入历史条数
```

### 对话：重命名与删除

- 新迁移 `005_session_deleted_at.sql`：`sessions` 表加一列 `deleted_at TEXT`。删除对话是**软删除**。
- `PATCH /sessions/{thread_id}`，请求体为 `{ title }`。后端先去掉首尾空白，长度要在 1 到 `conversation_title_max_length` 之间，不满足就返回 422。别人的、不存在的、已删除的对话一律返回 404。返回更新后的 `{ thread_id, title }`。
- `DELETE /sessions/{thread_id}`：设置 `deleted_at`，并把这个对话下所有运行里 `status='pending'` 的待确认写入（不管是否已经超过 24 小时）改为 `rejected`。这两步放在同一个事务里完成。成功返回 204。别人的、不存在的、已删除的对话返回 404。
- 不删除 `runs`、`run_steps`、`pending_writes`、`saved_queries`，也不删除 LangGraph checkpoint。
- `GET /sessions` 和 `GET /sessions/{thread_id}/runs` 都要过滤掉 `deleted_at IS NOT NULL` 的对话，后者对已删除的对话返回 404。
- `GET /sessions` 的每一项增加 `pending_write_count`，即没过期、仍是 pending 的待确认写入笔数，供删除确认框使用。
- `/chat/stream` 收到一个已删除对话的 `thread_id` 时返回 404，不能让它「复活」。界面上点不到这种情况，这里只是兜底。
- 用户改过的标题系统永远不再覆盖。现在没有自动改标题的逻辑，所以不需要加标记列；以后如果加自动标题，要满足这条。
- `database.session()` 生成自动标题时，改用 `conversation_title_auto_length` 截取。已经存在的旧标题不回填。
- 前端：
  - 「⋯」按钮在悬停或选中时显示，菜单是一个小浮层，结构参考 issue 里的截图。
  - 重命名在原位置编辑。前端不限制输入长度，422 的错误文案直接显示出来。
  - 删除使用 `confirm` 级别的确认框。删掉当前对话时，复用「＋ 新对话」的逻辑。

### diff 卡上文：并入回执，不新开接口

- `preview()` 和 `preview_budget()` 的回执里增加 `context_before: string[]`：从目标文件中取插入点之前的原文，最多 `ledger_context_lines` 行。如果取到的全是空行，就继续往上取，直到拿到足够的非空内容或者到达文件开头。目标文件不存在或为空时，返回 `[]`。
- 上文和 `insert_at_line` 在同一次 reload 中计算，保证行号一致。这就是不另开 `/ledger/raw` 的原因：分开请求的话，两次请求之间账本可能被手改，行号会错位。另外也少了一个「按路径读账本文件」的接口。
- 回放时，pending 状态的待确认写入会重新 preview，所以自然带上上文；已经是终态的写入，回执里没有 `context_before`，前端按空数组处理。
- 前端的 diff 卡把 `context_before` 显示成灰色、带行号（从 `insert_at_line - len` 开始）、不带 `+` 的行。
- 删除 `LedgerPanel` 里 `/ledger/raw` 的 `<Stub>`，以及 `api.ts` 里的 `ledgerSlice` 和 `LedgerSlice`。

### 写入历史：`GET /ledger/history`

- 从用户账本的 git 历史中，筛出提交信息以 `LedgerSage:` 或 `BeanChat:` 开头、动作是 `record`、`set budget` 或 `delete` 的提交，按时间倒序，最多取 `ledger_history_limit` 条。
- 再扫描 `LedgerSage: undo <sha12>` 提交，找出它们撤销的是哪个提交，据此给对应的条目标上 `undone_at`。撤销提交本身不进入列表。`initialize ledger` 和非 LedgerSage 的提交也不进入列表。
- 摘要由后端根据提交的 diff 生成，前端不解析 diff：
  - `record`：取第一笔新增交易的头行，格式为 `MM-DD 收款方/描述 金额`；如果有多笔，再加「等 N 笔」。
  - `delete`：取被删除交易的头行。
  - `budget`：格式为 `显示名 预算 → 金额`。
- 返回格式：

```jsonc
[
  {
    "commit": "a1b2c3d4e5f6…",
    "kind": "record" | "budget" | "delete",
    "summary": "10-21 地铁 −6 等 2 笔",
    "file": "2026/10-expenses.bean",
    "committed_at": "2026-10-21T21:03:00+08:00",
    "undone_at": "2026-10-21T22:10:00+08:00" | null
  }
]
```

- 只读，不需要拿写锁。
- 前端：
  - 在 `api.ts` 中新增 `ledgerHistory()`。
  - `LedgerPanel` 的 Ledger tab 里，把第二张 `<Stub>` 换成「写入历史」卡片，位置在预算进度下面。卡片是只读列表，**没有撤销按钮**。已撤销的条目变灰，并显示「已撤销 · 相对时间」。空状态显示「还没有 LedgerSage 写入」。接口失败时只有这张卡片报错。
  - 刷新时机：页面加载时、当前对话确认写入之后、顶栏健康度刷新时（统计页的删除和撤销已经会触发这次刷新）。不轮询。

### 统计页清理

- 删除 `Explore.tsx` 子导航里「持仓」和「BQL 查询」两个 `div.off`，以及 `explore.css` 里的 `.subnav .off` 样式。

### 查询账户前缀

- `AgentModel.query` 的签名改为 `query(message, accounts, today)`，`accounts` 的格式和 `extract()` 一样，都是 `(账户, 显示名)` 列表，去掉 `Equity:` 开头的账户。提示词要求 `account_prefix` 必须是其中某个账户，或它按段计算的前缀。
- 新增两个函数，所有地方都调用它们：
  - 规范化前缀：先去掉首尾空白，再去掉末尾的 `:`；结果为空串时视为不筛选。
  - 判断账户是否落在前缀下：账户 `== p`，或者以 `p + ":"` 开头。
- `query.py` 的两处正则改为 `^前缀(:|$)`；`ledger.py` 中 `query_transactions` 的 `startswith` 和 `graph.py` 中 `list_accounts` 的 `startswith` 都改用上面的按段判断。
- 校验：`query_transactions`、`get_balance`、`list_accounts` 执行前，先检查前缀下面有没有已开户的账户。没有的话就不执行查询，回复由代码生成，不调用 LLM：
  - 有候选时：「账本里没有 `X` 这个账户。你是不是想查：显示名（账户）？」
  - 没有候选时：「账本里没有 `X` 这个账户，可以问我『我有哪些账户』。」
  - 候选的生成顺序：先找显示名在用户原话里出现过的账户，再用 `difflib.get_close_matches` 补足（cutoff 0.6）。去重后最多 3 个，`Equity:` 开头的不参与。
- 这一期不转成追问：追问恢复后会重新分类意图，现在没有「带着选中的账户回到查询」的路径。
- 回复要写明查询口径：
  - 空结果：「起 至 止，显示名（前缀）没有记录。」
  - 有结果：「起 至 止，显示名（前缀）共 N 笔，支出合计 X。」
  - 显示名取前缀对应账户 `open` 指令上的 `name:`，取不到就只显示前缀。没有筛选时不提账户。

### 跨切面

- 所有新端点都通过现有的当前用户依赖做鉴权，数据按 `user_id` 隔离（ADR-0005）。
- 本期不新增 ADR。软删除、回执附带上文，都是容易反悔的局部决定。

## Testing Decisions

- 沿用上一期的做法：**只用一个 seam，就是 HTTP API**。用应用工厂加 `FixtureModel` 构造应用，通过 `TestClient` 发请求、断言 JSON。不单测内部方法。
- 准备数据：对话和运行用 `converse()` 驱动 `/chat/stream` 产生；账本内容通过工厂拿到账本后调用 `insert`、`delete`、`undo`，或者直接改写 `tmp_path` 下的文件，并自己执行 `git commit`，模拟手工提交。
- 要覆盖的行为：
  - 重命名：保存时去掉首尾空白；空串和超长返回 422；改别人的对话返回 404；改名后 `GET /sessions` 里能看到新标题；再发一条消息后标题不变。
  - 删除：删除后 `GET /sessions` 里没有它，回放返回 404；这个对话里 pending 的待确认写入变成 `rejected`，之后再 confirm 会被拒绝；从这个对话收藏的常用查询还在；已确认写入的记录还在；`/chat/stream` 用这个 `thread_id` 发消息返回 404；跨用户返回 404。
  - 自动标题：长消息只截取前 `conversation_title_auto_length` 个字。
  - 上文：在非空文件里预览，`context_before` 的末行就是插入点前的原文；空文件返回 `[]`；插入点前全是空行时，会继续往上取到非空内容；预算预览也带上文。
  - 写入历史：record、budget、delete 三种都会出现，而且是倒序；撤销之后原条目带 `undone_at`，撤销提交本身不出现；手工提交和 `initialize ledger` 不出现；`BeanChat:` 前缀的提交会出现；超过 limit 时被截断；摘要格式正确。
  - 迁移：`005` 能在已有数据库上升级。
  - 查询账户前缀：`query()` 收到的是不含 `Equity:` 的账户表；按段匹配不会命中 `Expenses:FoodDelivery`，`Expenses:` 等价于 `Expenses`；不存在的前缀不会执行查询，而是返回账户不存在的回复和候选，三个工具都一样；回复文案在带显示名、分组前缀、没有筛选三种情况下都正确。这部分是图层面的行为，按 `test_graph.py` 的方式用 FixtureModel 驱动。
- 参考的现有测试：`test_sessions.py`、`test_pending_writes.py`、`test_delete_transaction.py`、`test_ledger_status.py`、`test_migration.py`。
- 前端：仍然只用 `npm run build` 做类型检查，再加每张票里的手工验证。

## Out of Scope

- 在写入历史里直接撤销。
- 「查询命中的原始条目」：需要先让查询工具返回 `file:lineno`，以后单独 grill。
- 把右栏做成常驻的账本文件查看器。
- 恢复已删除的对话、对话回收站、硬删除和数据清理。
- 对话的置顶、分组、搜索、分页，以及用 LLM 自动生成标题。
- 回填已有对话的标题。
- 写入历史里列出用户的手工提交。
- 查询时账户不存在转成追问，以及按 payee 查询的同类问题（payee 目前是包含匹配，不在本期范围）。
