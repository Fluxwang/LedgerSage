# 账本目录是 git 仓库，撤销即 revert

写入是纯追加（见 ADR-0002），因此「撤销一笔刚记的交易」需要一个能精确定位并移除那段文本的机制。我们让每个账本目录本身是一个 git 仓库：每次写入后对被改动的那一个文件单独 commit，撤销就是 `git revert`。

## Considered Options

- **按字节偏移截断**被否决：账本文件预期会被用户用编辑器手工修改（现有账本就有手工提交记录），一旦文件在写入与撤销之间被外部改动，偏移就指向错误位置，会静默删掉别的交易。
- **只记反向分录、永不修改历史**（复式记账的正统做法）被否决：交互上对新用户太不友好，且拿不到审计线。

## Consequences

- 撤销之外顺带获得：完整审计线、任意时刻回滚、Agent 写入与用户手工编辑共处同一条 git 时间线。
- Docker 镜像必须安装 git；模板生成新账本时要 `git init`。
- 提交时必须 `git add` 精确到本次写入的那一个文件，绝不能 `git add -A`——否则会把用户正在手工编辑的其他文件卷进 Agent 的提交。
- 每笔交易一个 commit，git log 会很吵；提交信息需要统一格式以便区分 Agent 写入与人工提交。
