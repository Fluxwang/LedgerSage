# 一条消息里的多笔交易整批原子

一条消息可以包含多笔账（「早饭12 打车32 咖啡28」）。只要其中任意一笔信息不全，整批挂起、逐笔追问补齐，全部齐备后一次性写入并打成**一个** git commit；撤销时整批一起撤。

## Consequences

- 允许部分成功会产生难以解释的中间态：三笔写进去两笔、第三笔还在等回答，而用户此时刷新页面或干脆不回答，账本里就留下半批数据，回执上的撤销该撤几笔也说不清。整批原子直接消掉了这个状态空间，并与 git commit 的粒度对齐（一个 commit = 用户的一次意图）。
- 代价：一笔问不明白，另外两笔也写不进去。
- 挂起状态需要记住「数组里第几笔在等哪个字段」，比单笔复杂一档。
- **记账与查询不能混在同一条消息里**。「早饭12，对了这个月餐饮多少钱」判为 `other` 并追问让用户拆开，不在一次运行里既写又读。
