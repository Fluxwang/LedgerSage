# 意图置信度由 LLM 自报，账户置信度由历史频次计算

「低于阈值就停下来追问」是本系统的核心安全机制，因此置信度必须有可复现的定义。我们对两类置信度采用不同来源：**意图**置信度由 Classify 节点的 LLM 自报，仅作粗筛（低于 0.6 转追问，不细分）；**账户与分类**置信度由该商户/品类的历史交易中最高频账户的占比算出，阈值 0.70 作用在这个频次上。

## Consequences

- 账户置信度可单测、可复现，并且面板上能直接展示证据（「火锅 8 次里 6 次走微信」），而不是一个无法解释的模型自评分。
- 不迷信 LLM 自报分数：它未经校准，能区分「很确定」与「完全不确定」，但区分不了 0.65 与 0.75。
- 新用户或新商户没有历史，频次无从计算，一律走追问。冷启动阶段追问会偏频繁，这是刻意接受的代价。
- 设计稿 `frontend/index.html` 中「历史 6/8 却给出 account confidence 0.41」的数字是画稿时的占位，不构成实现依据。
