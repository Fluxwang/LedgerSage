# 账本写入是纯追加的，且服务必须单进程

账本文件是账务数据的唯一真源，而原实现每写一笔就 shell 出去跑 `bean-format -o <file> <file>`，即把整个文件读入再整体写回——两个并发写会用旧快照覆盖掉对方。现在写入退化为纯 append（`EntryPrinter` 输出的文本本身已是规范格式），并发由「每本账本一把进程内 `asyncio.Lock`」串行化。

## Consequences

- **uvicorn 必须以单 worker 运行。** 进程内锁跨不了进程；一旦为了吞吐加 `--workers N`，并发写会重新变得不安全。这是本项目已知的、被接受的扩展性上限。
- `bean-format` 不再是运行时依赖，Docker 镜像里不必安装；它降级为可选的人工维护命令。代价是历史文件的对齐格式不再被自动维护。
- 写入目标文件必须在**每次写入时**按当前日期计算，而不是在 bootstrap 时算死——否则服务跨月后仍会写进上个月的文件。

## Amendments

- ADR 0013 开了一个例外：**删除交易**走读—改—写，不再是追加。记账与预算写入仍然是纯 append。单 worker 的约束不变，而且因为出现了读改写而更加要紧。
- ADR 0012 把记账与预算写入拆成了「预览 + 确认」两段。这不影响本 ADR——pending 期间不写文件，确认时仍是一次纯 append。
