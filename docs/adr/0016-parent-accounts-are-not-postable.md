# 有子账户的账户不能直接记账

收支表要按账户层级出矩阵，中间层（`Expenses:Food`）需要中文显示名，而预算本来就要求账户先 `open`（ADR 0008）——于是汇总账户会被正式开户。但对话记账的候选就是全部已开户账户，汇总账户一开户就会混进候选，模型可能把「买了点吃的」直接记到 `Expenses:Food` 上，收支表里「饮食」就多出一块不属于任何子类、下钻也找不到的钱。我们决定：**下面有子账户的账户（汇总账户）只用来挂预算、出报表和做筛选前缀，对话记账的候选与待确认写入的编辑都不再提供它**；是不是汇总账户完全由账户树结构推出，不另设 meta 标记。

## Considered Options

- **允许直接记账，报表多出一行「未细分」**：被否决。它把分类不全的问题从记账时推迟到看报表时，而且「未细分」会一直累积——每一笔都是模型替用户做的模糊选择，事后没有人会回去拆。
- **用 meta 显式标记哪些账户可记账**：被否决。账户树本身已经包含这个信息，另设标记就多了一处会和树结构不一致的状态。

## Consequences

- 这条规则只约束**新的**对话写入。账本原文里已有的、直接记在汇总账户上的交易（手写的，或该账户后来才长出子账户）照样合法，`bean-check` 也不会拦。因此报表里汇总账户的金额按「自身分录行 + 全部子孙账户」算，而不是只加子账户，旧数据不会从报表里消失。
- 给一个已有交易的末级账户新开子账户，会让它变成汇总账户、从此不能再记账。这是预期行为，不做迁移。
- 预算不受影响：设预算的账户反而通常是汇总账户，它统计已用时本来就按段前缀累计子账户。
